# v0.2.57 verification - carpet/window flicker and cutscene wait (#67)

Base: `release/v0.2.56` (`7202b31`). Changes: `ORDER1886_REDRAW_SLOPE_BIAS` default 1.0 -> 0.25,
`ORDER1886_COMPILE_WAIT_MS` default 100 -> 33, launcher version 0.2.57, and a tag-driven release
workflow (`.github/workflows/order1886-release.yml`) that calls the two package workflows.

## Flicker (#67): measured

Windows 11, RTX 5050 Laptop (driver 32.0.16.2140), v0.2.56 package, CUSA00785 1.02.

The launcher drops inherited `ORDER1886_*` variables except `DIAGNOSTIC_ENVIRONMENT`
(`order1886.py`, `runtime_process_environment`), so the runtime was started directly with the
launcher's own command line and environment from `user/order1886/logs/last-run.json` plus the
test value. The console log of each run records the value
(`issue67-mode2-<time>.log`, first line).

| Slope bias | Carpet room | Face close-up |
|---|---|---|
| 1.0 (v0.2.56 default, through the launcher) | the whole carpet pops in and out; the floor is drawn over it, only its edge stays | clean |
| 0 | carpet stays | black hexagonal dots (#27) |
| 0.25 | carpet stays | clean |

Frame stats with the slope bias at 0: 60 FPS, worst frame ~18 ms once shaders had compiled.

## Cutscene wait (#67, #61): not measured

v0.2.56's own measurement (commit `81d897f`): cold cache, Chapter I opening, worst frame
745 -> 1773 ms with the 100 ms bucket. 33 ms caps the wait at one 30 FPS frame per burst, between
v0.2.49 (no wait) and v0.2.56. Not played with the new value.
