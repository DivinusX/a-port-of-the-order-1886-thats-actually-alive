## RESOLVED (later same day): the examine-prompt glyph bug was cache poisoning, not UI_SITES

The owner's A/B initially looked bars-related, but the clone experiment disproved it: the
**same prepared image** rendered the triangle with a cold cache and hid it when replaying the
warm one. Bisect: deleting only the 28 shaders that logged `SRT offset failure` (fallback to
unflattened reads) from the pipeline cache — 59 blobs — restored the glyph in BOTH aspect
modes (`7298 of 7328 pipelines` replayed, 30 correctly stale). Mechanism: the flatten pass's
failure decision depends on live SSA shapes and was never persisted; the meta described the
flattened layout while the binary read canonical tables, so every replay of such a pipeline
bound the wrong descriptor and the glyph sampled nothing.

Engine fix (local commit `87c69aac27` on `aot-shader-cache`, NOT pushed — owner rule):
`InfoPersistent::srt_offset_fallback` set by `ReportOffsetFailure`, serialized in the meta,
`LoadShaderMeta` refuses flagged entries (always live-compile = the provably correct path),
`ShaderMetaVersion` 10→11 so every existing poisoned cache self-invalidates once.

Remaining before shipping: local build verification (`build.sh`, first attempt failed on a
stale `out/gpu` CMake cache missing `-L deps/root/usr/lib` for Zycore — clean reconfigure
running), then E2E: play with the fixed runtime, quit, relaunch, glyph must survive the
replay (the version bump forces one fresh compile pass first).

## ADDENDUM (23:30 local): prompt-glyph investigation — refusal is load-bearing, race remains

Owner re-tested v0.2.26 live on this machine. Findings, in order:

1. Cold cache (live compile) = broken prompt disc (no ring/glyph, crescent only). Warm
   replay = sometimes fine (runs 2/3), sometimes broken — NOT deterministic, so the
   original "poisoned replay" model was incomplete.
2. Experiment: removed the LoadShaderMeta replay refusal, local GCC build, empty cache.
   Result: SIGSEGV inside libvulkan_radeon during WarmUp replay of flagged fallback
   pipelines (stack: LoadGraphicsPipeline -> CreateCachedGraphicsPipeline). The refusal
   is REQUIRED and now carries that comment in the code. (Local-vs-release compiler ABI
   mismatch also explains an earlier crash scare — local builds must use their own caches.)
3. Remaining bug, precisely scoped: the async first-compile of the prompt's shaders
   snapshots the live SRT/descriptor tables while the game is still updating them; the
   snapshot is sometimes wrong (broken widget) and the permutation system does not
   self-correct on later draws (verified: 10+ s idle stays broken). Next session: gdb
   watchpoint on the table memory during the office-desk prompt draw; candidate fixes:
   (a) re-verify spec after publish, (b) compile flagged variants synchronously at first
   encounter, (c) force a spec recheck per draw for fallback programs.
4. v0.2.26 stays as shipped: it fixes the crash-prone replay and the permanent-poison
   case; the cold-run artifact is the race above, pre-existing, self-heals across sessions.


## ADDENDUM 2 (23:55 local): the crash unifies everything — it is ReadConst sizing

Owner's normal session (release binary, refusal active) CRASHED at the desk with:
SRT fallback on shader 0x000000000f3ced99 (fs) -> GPUVM fault at guest VA 0x908002e14000
(CLIENT_ID SQC-data, PERMISSION_FAULTS=3) -> RADV hard recovery -> device lost ->
vk_scheduler SubmitExecution assertion. Glyphs were rendering correctly when it died.

Unified model: the fallback variants' ReadConst bindings are sized from the compiler's
static `readconst_size_bytes` estimate; the game's runtime dynamic index can exceed it.
- Fault lands in junk-but-mapped memory -> reads garbage/zero -> invisible glyph (the
  prompt bug: deterministic per session, explains why waiting never fixes it and why it
  varies across sessions/lineages).
- Fault lands outside mappings -> GPUVM fault -> GPU reset -> crash (tonight).
- Replay of such a pipeline crashes at creation (the SIGSEGV when refusal was removed).

Fix direction (next session, carefully):
1. Bind ReadConst descriptors from the ACTUAL SHARP contents at draw time (they are
   re-read per draw anyway) instead of the static estimate, clamped to the mapped region.
2. Or clamp the index in generated code for fallback variants (bounds-checked read).
3. Keep the replay refusal; it is load-bearing.
4. Owner guidance meanwhile: the desk-area crash is random (GPU-side), not save-corrupting
   (the game autosaves per checkpoint; recovery verified). Avoid lingering at examine
   prompts in the prologue office until the fix ships.

v0.2.26 remains the shipped state: it eliminated the crash-at-replay class; the
live-compile GPUVM fault is pre-existing (fallback path dates to the original port).
