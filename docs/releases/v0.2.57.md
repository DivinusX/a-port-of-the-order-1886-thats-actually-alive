# v0.2.57 - flickering carpets and windows, cutscene stutter
## Which file do I download?

| File | What it is |
|---|---|
| 🪟 `order1886-win-x86_64-v0.2.57.zip` | **Windows: download this** for a new install or a manual update. |
| 🐧 `order1886-linux-x86_64-v0.2.57.tar.gz` | **Linux: download this.** Extract it over your installation, keeping your `user/` folder. |
| `order1886-go-windows.zip` | **Windows auto-updater package.** The launcher downloads it when it updates. Same archive as the versioned Windows zip. |

v0.2.57 is v0.2.56 with the two settings behind the regressions in [#67](https://github.com/DivinusX/a-port-of-the-order-1886-thats-actually-alive/issues/67) corrected. Saves and settings in `user/` are kept.

## What's fixed

### Carpets, windows and frames flickering indoors ([#67](https://github.com/DivinusX/a-port-of-the-order-1886-thats-actually-alive/issues/67))

**Cause:** the v0.2.56 fix for black spots on faces (#27) gives the lighting pass a little extra depth room that grows with how steeply a surface is seen. It was set too high: a floor seen at a shallow angle got enough room to be drawn over the carpet lying on it, so the whole carpet popped in and out as the camera moved. Windows and frames on walls flickered the same way.

**Fix:** the extra room is a quarter of what v0.2.56 used. Tested on an RTX 5050 in the same room and on face close-ups: with the v0.2.56 value the carpet pops, with none the face spots come back, with the new value both are right.

### Stutter at cutscene camera cuts ([#67](https://github.com/DivinusX/a-port-of-the-order-1886-thats-actually-alive/issues/67), [#61](https://github.com/DivinusX/a-port-of-the-order-1886-thats-actually-alive/issues/61))

**Cause:** to stop faces going black after a cut, v0.2.56 waits for shaders that are still compiling, up to 100 ms at once. On a fresh shader cache (the first launch after every update) that was a visible hitch at each camera cut.

**Fix:** the wait is capped at 33 ms at once (one frame at 30 FPS). Shaders that take longer are skipped for a frame or two, as before v0.2.56, instead of freezing the picture. Once compiled, shaders are cached and later visits are smooth.

## Verification

Both packages build from the same commit in one release run (see `release-verification.json`); native checks and the portable smoke ran on both, and the Linux smoke re-ran on the finished archive. The flicker fix was measured on Windows with an RTX 5050 by running the v0.2.56 runtime with each value in the carpet room and on face close-ups.

**Not covered yet:** the new cutscene wait was not measured in game, and the packaged v0.2.57 was not played before release. AMD GPUs, the ROG Ally and Linux gameplay were not run. If something got worse for you, please attach your log.
