v0.2.63 is v0.2.62 with fixes for unnecessary texture cleanup thrashing and buffer stalls on 8 GB GPUs (RX 6600 and similar) and per-frame maintenance timing. Saves and settings in `user/` are kept.

## What's fixed

### FPS drops and texture thrashing on 8 GB GPUs ([#71](https://github.com/DivinusX/a-port-of-the-order-1886-thats-actually-alive/issues/71))

- **8 GB VRAM thresholds fixed:** on 8 GB discrete cards (`~6.3 GB` budget after desktop reserve), the texture-cache garbage collector previously started at `0` MB and treated `~2.52 GB` as "under memory pressure". At ~4.2 / 7 GB in gameplay, the cache stayed stuck in constant pressured cleanup, unloading active textures and render targets and reloading them again. Discrete GPUs up to 10 GB now use `70%` / `82%` / `90%` thresholds while preserving the 4 GB headroom fix from v0.2.62 (`#73`).
- **Frame-paced GC & staging cache lifetime:** texture GC and staging-buffer trimming previously ticked once per GPU command submission (65–80 times per frame) instead of once per frame, causing textures <1 frame old to be evicted mid-frame, thousands of driver memory-budget queries per second, and staging blocks to be freed after ~0.65 seconds instead of ~30 seconds. Both now run once per GPU frame (`FrameCadence`) alongside a combined single Vulkan memory-budget query.

## Please test

- **#71:** if you had FPS drops on an 8 GB card (RX 6600, RTX 3070, RTX 4060, etc.) when walking through areas or during combat, please try v0.2.63 and report whether frame pacing stabilizes.

Both packages build from the same commit in one release run (see `release-verification.json`); native checks (including updated 8 GB RX 6600 budget and `FrameCadence` tests in `texture-cache-budget-test`) and the portable smoke ran in CI and in a local Linux Clang test build on an AMD Radeon RX 9070 XT.
