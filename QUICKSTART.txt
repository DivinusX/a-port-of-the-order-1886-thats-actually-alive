THE ORDER: 1886 FOR PC - QUICK START (LINUX)

WHAT THIS DOWNLOAD INCLUDES

"The Order 1886" (the launcher), "Play The Order 1886" (direct play), the
launcher window in bin/order1886-launcher, the dedicated compatibility
runtime and its libraries in bin, and license notices. This is unofficial,
emulator-backed compatibility software, not an official PC port.

No game executable, game archives, firmware or player saves are included.
Use your own extracted PS4 copy of The Order: 1886, in any edition:
CUSA00076 (tested), CUSA00035, CUSA00070, CUSA00100, CUSA00670 or CUSA00785
(experimental: report how they run). Update 1.02 may be applied or not.

REQUIREMENTS

- x86-64 Linux with glibc 2.39 or newer and a Vulkan driver for your GPU.
- The launcher window needs WebKitGTK 4.1 (libwebkit2gtk-4.1.so.0), for
  example the webkit2gtk-4.1 package on Arch or libwebkit2gtk-4.1-0 on
  Debian and Ubuntu. Playing does not need it.
- Extract the complete archive to a writable folder. Keep both entry points
  and bin together.

YOUR GAME FOLDER

Choose the folder that directly contains eboot.bin, archivemap.bin, _data,
sce_sys and sce_module (any folder name). The original files are only read.

WITH WEBKITGTK 4.1

Start "The Order 1886", choose your game folder on Game & Content, then press
Play. "Play The Order 1886" later starts the game directly with the saved
settings.

WITHOUT WEBKITGTK 4.1 (STEAMOS / STEAM DECK)

SteamOS does not include WebKitGTK and replaces its system files on every
update, so the launcher window cannot open there. The game still plays:

1. Put your game folder next to the extracted "The Order 1886" folder, or
   note its full path.
2. In Steam (Desktop Mode): Games > Add a Non-Steam Game, browse to
   "Play The Order 1886" and add it.
3. If the game folder is not next to the package, open the entry's
   Properties and set the launch options to:
     --game-dir "/home/deck/Games/CUSA00076"
   with your own path. It is checked and saved on the first start, so you
   can remove it afterwards.
4. Start it from Steam, in Game Mode or Desktop Mode.

Settings keep their defaults (30 FPS) until you change them in the launcher
window, for example on another PC with the same "user" folder. While playing,
F10 cycles the frame rate live: 60, 90, 120, back to 30 (rates above 60 need
a display that refreshes that fast, or VSync off). Starting
"The Order 1886" without WebKitGTK shows what is missing and then plays the
saved settings. The message is also written to
user/order1886/logs/launcher-entry.log.

To get the launcher window on SteamOS anyway, install WebKitGTK through
Homebrew and expose only its two libraries; see issue #114 on GitHub for the
exact commands.

CONTROLLERS (XBOX, PLAYSTATION, OTHER GAMEPADS)

The game reads controllers through SDL3, which uses each pad's HID
interface (/dev/hidraw*). If your controller connects but no buttons do
anything in game, in this order:

1. Steam is the usual cause: its desktop controller support grabs gamepads
   exclusively, so the game sees the pad but receives no input. Either exit
   Steam while playing, or turn off Steam Settings -> Controller ->
   "Enable Steam Input" for Xbox/PlayStation controllers.
2. If it also fails with Steam closed, your session does not grant HID
   access to gamepads (common on Bluetooth pads and some display managers).
   Fix with either:
     sudo usermod -aG input $USER      (then log out and back in)
   or a udev rule:
     echo 'SUBSYSTEM=="hidraw", ATTRS{id/vendor}=="045e|054c|057e|28de|0fd9", MODE="0660", GROUP="input", TAG+="uaccess"' \
       | sudo tee /etc/udev/rules.d/99-gamepad-hidraw.rules
     sudo udevadm control --reload && sudo udevadm trigger
   The launcher prints a one-line warning to its log when a gamepad HID is
   present but not readable, so you can tell this case apart from Steam.
3. Bluetooth pads sometimes hold a dead link after sleep: press the Xbox/PS
   button for 3 seconds to sleep the pad, then press again to reconnect.
4. Wired and wireless at the same time: the game uses the first controller
   it finds. Unplug the one you do not want to use.

UPDATING

Extract the new archive and copy your "user" folder from the old one into
it. It holds settings, saves and logs.
